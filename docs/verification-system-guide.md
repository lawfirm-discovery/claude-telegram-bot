# ERP 메뉴 검증 시스템 가이드

## 구성 파일

| 파일 | 용도 |
|------|------|
| `docs/verification-checklist-template.md` | 검증 항목 정의 (A~E 카테고리, 총 47개 항목) |
| `docs/iteration-log-template.md` | 반복별 결과 기록 템플릿 |
| `reports/{타입}-iter{N}-{날짜}.md` | 실제 반복 기록 (템플릿에서 복사) |

## 카테고리별 검증 항목 수

| 카테고리 | 항목 수 | 핵심 초점 |
|----------|--------|----------|
| A. 기능성 | 21 | API 정합성, CRUD, 비즈니스 로직, 라우팅 |
| B. UI/UX | 14 | 반응형, 모달, 테이블, 다크모드 |
| C. 성능 | 7 | 로드 시간, 리렌더링, 메모리, N+1 |
| D. 에러 처리 | 10 | HTTP 에러, 중복 요청, fallback |
| E. i18n/a11y | 5 | 번역, 날짜/숫자 형식, 키보드 접근성 |

## 워크플로우

```
1. 전문가 타입 선택
   └─ 해당 타입의 메뉴 목록 파악 (EXPERT_TYPES.md 참조)

2. 반복 시작
   ├─ verification-checklist-template.md 기준으로 검증
   ├─ 이슈 발견 → 즉시 수정 또는 이월 판단
   └─ iteration-log-template.md 복사 → reports/ 에 결과 기록

3. 반복 종료
   ├─ 통과율/커버리지 계산
   ├─ 미해결 항목 → 다음 반복으로 이월
   └─ git commit

4. 반복 기준
   ├─ 통과율 100% + 커버리지 90% 이상 → 완료
   └─ 미달 → 다음 반복에서 FAIL/SKIP 항목 재검증
```

## 심각도 기준

| 심각도 | 기준 | 대응 |
|--------|------|------|
| CRITICAL | 서비스 불가, 데이터 유실, 보안 취약점 | 즉시 수정 |
| HIGH | 핵심 기능 동작 불가 (CRUD 실패, API 404) | 같은 반복 내 수정 |
| MEDIUM | 부가 기능 불량, UI 깨짐 (사용은 가능) | 다음 반복 수정 가능 |
| LOW | 미관, 사소한 텍스트, 권장사항 미준수 | 백로그 |

## 이슈 ID 규칙

```
ISSUE-{타입약어}-{iterN}-{번호}

타입약어:
  LAW = 변호사    TAX = 세무사    PAT = 변리사
  JUD = 법무사    ACC = 회계사    CUS = 관세사
  APP = 감정평가사 ADM = 행정사    LAB = 노무사
  NOT = 공증인    STN = 속기사

예: ISSUE-ACC-R8-01 = 회계사 라운드8 이슈 1번
```
